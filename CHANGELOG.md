# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-09-29

First release of the Hive Axyl SDK for Unity — a modular UPM package set for the Hive Axyl platform, covering Android (API 29+), iOS (17+), macOS (15+), Windows (11 64-bit+), and WebGL (WebGL 2.0) — support varies per package.

For the packages that support WebGL, it uses the same 1.0.0 API and Semantic Versioning as the other platforms. WebGL verification has not been completed for this release; issues it finds will be fixed in later releases.

Windows additionally requires the Microsoft Visual C++ 2015–2022 Redistributable (x64) on every machine that runs the game, including your own while developing.

### Added

- Auth: `AuthGetBlockStatusResult.BlockTypeContentNotFound` — the block type exists but carries no content for the default language, so there is no message to show the player. It is distinct from `BlockTypeNotFound`, which says the block type itself is unknown: the first is missing copy on a real restriction, the second a restriction that does not exist.
- Auth: `TokenIssueTokenResult.TemporarilyUnavailable` — the store could not be reached. It is the only retryable outcome on token issue; the others give the same answer however often they are sent. Back off rather than retrying immediately — the contract states the code is retryable and leaves the interval to the caller.

#### Core

- `com.com2usplatform.hiveaxyl.core` — the SDK runtime every other package builds on. `HiveBootstrap.Initialize(config, b => b.AddAuth()...)` boots the SDK, registers the selected capabilities and add-ons, and forwards application lifecycle events; resolve any registered service with `HiveCore.Resolve<T>()` or `HiveCore.TryResolve<T>()`. WebGL builds bundle the browser runtime, so no host-page wiring is needed.
- Typed result model: every API call returns a `{Method}Result` with a `Success` variant, typed outcome variants for contract-declared error codes, `UnknownOutcome` for outcome codes newer than the SDK, and `Failure` for infrastructure problems (network, timeout, cancellation), marked with the cross-cutting `IUntypedProblem` interface. Every variant exposes the original response body via `RawResponse`, so a server-added field is readable without regenerating the SDK.
- Networking: automatic retry with exponential backoff, jitter, and `Retry-After` support; per-call timeout, retry, and logging policy via `ApiCallContext` / `RequestOptions`; automatic common headers and W3C `traceparent` request tracing; structured logging with PII masking.
- Session management with automatic token refresh: on a 401 the SDK refreshes the session once and replays waiting requests. Only the server's verdict that the refresh token itself is invalid ends the session (raising `OnSessionExpired`); a transient failure never destroys the stored credentials (three consecutive no-verdict failures end the in-memory session; the persisted credentials survive).
- Per-call credential: `ApiCallContext.Credential` selects `Ambient` (the SDK session), `Anonymous` (no `Authorization` header), or `Bearer(token)` (a caller-supplied token), with `WithAccessToken(token)` as the shorthand for validating a stored token during session restore before committing it.
- `HiveCore.SetLanguage(tag)` — override the `Accept-Language` sent to the server at runtime, independently of the device OS locale.

#### Server capabilities

- `com.com2usplatform.hiveaxyl.auth` — Auth and Token clients (`IAuthService` / `ITokenService`): guest, provider, username, and custom-provider login, provider token exchange, token issuance, and logout. `AuthTokenRefresh.Enable` wires the automatic session refresh. On token issue, `TokenIssueTokenResult.TemporarilyUnavailable` is the one outcome worth retrying — the store could not be reached. Login and token endpoints are called without a session, so an expired session can never break a login. Auth and Token run on the core host, `https://core-api.hiveaxyl.com`. The spec declares no sandbox for either, so no sandbox overload is generated and asking for one does not compile; `AddAuth(baseUrl)` / `AddToken(baseUrl)` take an explicit host. Server API: `/auth/v1/`, `/token/v1/`.
- `com.com2usplatform.hiveaxyl.payments` — Payments client (`IPaymentsService`): the PG / Apple / Google / Steam purchase flow — payment page URL, pre-purchase, post / finalize / restore purchase, and subscriptions. Receipt verification is a server-to-server call the spec marks server-only, so it is not part of this client. `Price` and `Currency` are optional on `PurchaseRequest` and only serve the server's amount comparison, but required on `PrePurchase` and `SubscriptionPurchaseRequest`, where an unset one is sent as `0` / `""` — set them, along with `Country` and `Language`, on those two. `Os` on the order request is the `OrderRequestOs` enum (`Windows` / `Macos` / `Android` / `Ios` / `Webgl`) — set it too: the unset default serializes as `ORDER_REQUEST_OS_UNSPECIFIED`, outside the server's accepted set. Required response properties come through non-nullable, so reading one needs no null check. Payments runs on its own commerce hosts: `AddPayments()` binds to `https://commerce-api.hiveaxyl.com` and `AddPayments(sandbox: true)` to `https://sandbox-commerce-api.hiveaxyl.com`. It is the only capability whose spec declares a sandbox server, so it is the only one handed the `sandbox:` overload. Server API: `/payment/v1/`.
- `com.com2usplatform.hiveaxyl.push` — Push client (`IPushService`): register / sync a push token, change its language and receive-consent, and unbind. Push runs on the app host, `https://app-api.hiveaxyl.com`. The spec declares no sandbox for push, so no sandbox overload is generated and asking for one does not compile; `AddPush(baseUrl)` takes an explicit host. Server API: `/push/v1/`.
- `com.com2usplatform.hiveaxyl.mailbox` — Mailbox client (`IMailboxService`): send, list / retrieve / delete sent and received mail, mark-read, and recall. An attachment's `AttachmentType` is optional and starts at `"DEFAULT"`, so an attachment with no type set is a request the server accepts. `SendMailRequest.SenderDisplayName` is required — the sender name recipients see, captured at send time so a later rename does not reach mail already sent. Mailbox runs on the app host, `https://app-api.hiveaxyl.com`. The spec declares no sandbox for mailbox, so no sandbox overload is generated and asking for one does not compile; `AddMailbox(baseUrl)` takes an explicit host. Server API: `/mailbox/v1/`.
- `com.com2usplatform.hiveaxyl.serviceaccess` — Service Access-Control client (`IServiceAccessService`): maintenance info, client-update check, and country-block check. Callable before login. `X-Hive-Country-Code` is injected by the gateway from the caller's IP, so the SDK never sends it and the country the server resolved comes back in the response. Service Access-Control runs on the core host, `https://core-api.hiveaxyl.com`, alongside auth and token. The spec declares no sandbox for it, so no sandbox overload is generated and asking for one does not compile; `AddServiceAccess(baseUrl)` takes an explicit host. Server API: `/service/v1/`.
- `com.com2usplatform.hiveaxyl.tcb` — TCB (Tencent CloudBase) client (`ITcbService`): execute a Cloud Function stored on TCB. TCB runs on the app host, `https://app-api.hiveaxyl.com`. The spec declares no sandbox for tcb, so no sandbox overload is generated and asking for one does not compile; `AddTcb(baseUrl)` takes an explicit host. Server API: `/tcb/v1/`.
- `com.com2usplatform.hiveaxyl.coupon` — Coupon client (`ICouponService`): redeem a coupon code a player entered. A successful redemption delivers the reward to the player's mailbox and returns the mail receipt id (`MailId`); whether the player took delivery is a separate mailbox question. Every rejection the player can act on — an unknown code, a malformed one, an expired or not-yet-started coupon, an already-used one, a disabled one, and the account / group / total usage limits — is its own typed outcome variant, so the message shown to the player is chosen by matching the result, not by parsing a string. Coupon runs on the commerce host, `https://commerce-api.hiveaxyl.com`. The spec declares no sandbox for coupon, so no sandbox overload is generated and asking for one does not compile; `AddCoupon(baseUrl)` takes an explicit host. Server API: `/coupon/v1/`.
- `com.com2usplatform.hiveaxyl.analytics` — Analytics client (`IAnalyticsService`): post a batch of client log events. `CollectClientLogAsync` keeps the ambient credential: with a session, the token rides along and the gateway derives the player from it; before sign-in the header is simply absent — one intake covers both sides of login. Only `EventTime` and `EventName` are required on an event; anything past them is the game's own, and `AdditionalProperties` on an event takes them by name, each value a raw JSON literal (`"42"`, `"\"gold\""`, `"[1,2]"`), and they are written flattened into the same JSON object as `EventName` rather than nested under a key. Registered with `b.AddAnalytics()`, which binds it to its own production host, `https://data-api.hiveaxyl.com`. The spec declares test and production only, so no sandbox overload is generated and asking for one does not compile; `AddAnalytics(baseUrl)` takes an explicit host. Server API: `/analytics/v1/`.

#### Local capabilities

- `com.com2usplatform.hiveaxyl.storage` — SecureStorage (`ISecureStorage`): encrypted key-value persistence over each platform's secure store — Android (encrypted DataStore), iOS / macOS (Keychain), Windows (DPAPI) — with typed `DataCorrupted` / `AccessDenied` outcomes for recovery handling. No server calls.

#### Auth add-ons

- `com.com2usplatform.hiveaxyl.auth.addon.apple` — Sign in with Apple on iOS / macOS (`IAppleSignInPlugin`). The build post-processor enables the capability and entitlement in the generated Xcode project automatically.
- `com.com2usplatform.hiveaxyl.auth.addon.credentialmanager` — Google sign-in on Android via the Credential Manager unified picker (`IAndroidCredentialManagerPlugin`), returning the Google ID token credential with the stable account id (`UniqueId`) to use as `providerUserId`.
- `com.com2usplatform.hiveaxyl.auth.addon.gpg` — Google Play Games Services v2 sign-in on Android (`IGooglePlayGamesPlugin`): silent auth check, interactive sign-in, and server-side access code retrieval.
- `com.com2usplatform.hiveaxyl.auth.addon.steam` — Steam authentication on Windows / macOS (`ISteamPlugin`): Web API session tickets via `ISteamUser::GetAuthTicketForWebApi`, with explicit ticket release.
- `com.com2usplatform.hiveaxyl.auth.addon.webauth` — OAuth 2.0 external user-agent flow (`IExternalUserAgent`) on Android (Chrome Custom Tabs), iOS / macOS (`ASWebAuthenticationSession`), Windows (loopback redirect), and WebGL (browser popup). User cancellation surfaces as a typed outcome shared across every auth add-on (`IUserCanceledOutcome`).

#### Payments add-ons

- `com.com2usplatform.hiveaxyl.payments.addon.google` — Google Play Billing Library 9 on Android (`IGooglePlayBillingPlugin`): connection lifecycle, product query, purchase flow, restore, acknowledge / consume, and purchase-update events, with the raw Billing responses exposed without normalization.
- `com.com2usplatform.hiveaxyl.payments.addon.apple` — StoreKit 2 on iOS / macOS (`IAppleStoreKitPlugin`): products, purchase, entitlements, transaction history and observer events, finish / sync / storefront, with raw transaction and verification fields preserved.
- `com.com2usplatform.hiveaxyl.payments.addon.steam` — Steam Microtransactions on Windows / macOS (`ISteamMicrotransactionsPlugin`): the authorization-response callback listener and event.
- `com.com2usplatform.hiveaxyl.steamworks` — shared Steamworks infrastructure for the Steam add-ons, integrating Steamworks.NET.

#### Push add-ons

- `com.com2usplatform.hiveaxyl.push.addon.fcm` — Firebase Cloud Messaging on Android (`IFCMPlugin`): FCM token get / delete, cold-start notification read, and incoming-message / token-refresh events. The build hook applies Google's `google-services` Gradle plugin automatically — drop `google-services.json` into `Assets/Plugins/Android/` and Firebase initializes with no Gradle work.
- `com.com2usplatform.hiveaxyl.push.addon.apns` — APNs on iOS / macOS (`IAPNSPlugin`): device token, authorization request, notification settings, badge count, cold-start notification capture, and notification presented / opened / token-refreshed events. The build post-processor enables the Push Notifications capability and `aps-environment` entitlement automatically.
- `com.com2usplatform.hiveaxyl.push.addon.applenotification` — local notifications on macOS (`ILocalNotificationApplePlugin`): permission request, categories, time-interval and calendar scheduling, cancel / list, badge count, and notification presented / opened events. iOS is not covered — local notifications there are the Unity Mobile Notifications package's.
